## Findings and fixes

**Reading position (#97):** [hosted run 44953110864](https://github.com/utrost/Textr/actions/runs/44953110864) records API 29 **159/160**, with a 600 → 0 window-transition failure. `stateSaveCapturesPositionBeforeFrameworkViewCallbacks` independently fails before the fix: framework state-save callbacks clamp the old WebView before Textr reads it. Textr now captures reading position before `super.onSaveInstanceState` and consistently uses that snapshot. Pending find restoration also uses its authoritative position. Nineteen focused position/recovery/QoL cases, the full API 29 suite and ten transition repetitions pass afterward.

**Saved-copy opening:** a write-only provider reproduced a SecurityException when an internal same-app handoff forwarded read/delegation flags the provider never granted. The handoff no longer invents URI grants. Existing read access is retained only after successful reading; a read denial explains recovery while the completed write remains successful. No exported component or signature permission was weakened.

**Collection layout:** replacing the root during navigation could miss insets and clip Done. Root installation now requests insets after attachment; explicit full-visible-button checks pass at normal and 200% text. Direct screenshots were inspected.

**WebView source exposure (#59):** `ReaderUxTest.nativeSelectionAndIncomingTextShareThroughAndroid` reproduces a visibly correct “Copyable Textr selection” with only native toolbar/progress labels and an empty WebView body in refreshed Android nodes. Loaded source contents are independently exact. The required probe still finds exact visible text, then performs a real long-press and selected-text Share; it does not substitute coordinates for missing source exposure. Missing-node failures retain hierarchy XML, screenshot and node diagnostics. Global cache clearing is now being evaluated, not claimed as a production bridge fix. See [investigation](csv-accessibility.md); #59 remains open.

**Source-search layout (#128):** changing three matches to none deterministically moves the option touch target by **257 screen pixels** before the fix (`SourceSearchLayoutTest.asyncResultsKeepOptionTouchTargetsInPlace`, API 29). Clearing/repopulating rows changes the centered dialog height. Source search now reserves full window space, matching Structure/Accessible table, so asynchronous results cannot move controls between taps. The regression and five existing source/options/native-copy/200%-landscape cases pass on API 29 (**6/6**, 48.745 seconds). Debug/application-test builds, 102 JVM tests and lint pass afterward. This confirmed layout bug fits the differing option click heights in the failed hosted run; it is separate from WebView accessibility. The same six cases pass API 36 (42.386 seconds). The final expanded hosted matrix remains pending.

**Source-search keyboard (#129):** a native query tap fails to show a connected keyboard before the fix (12.444 seconds, API 29). Window diagnostics confirm `ALT_FOCUSABLE_IM`; Android's AlertDialog initially misses the editable ListView header, and the input-method server remains bound to the reader field behind it. Source search now clears that incorrect flag after dialog setup, retaining hidden-on-open/resize behavior. The connected-keyboard regression passes on API 29 / API 36 (3.307 / 3.927 seconds): native tap, actual shown keyboard, active dialog editor, real `N` key input and fully visible Done in portrait. API 29 dialog insets omit its shown IME in this environment, so that API requires both actual server visibility and this editor's connection; API 30+ uses native IME insets plus connection. It never accepts changed editor contents alone as keyboard proof. [Framework input detection](https://android.googlesource.com/platform/frameworks/base/+/refs/heads/main/core/java/com/android/internal/app/AlertController.java) explains the initially incorrect flag. Direct API 29 touch/typing smokes also pass normal portrait and 200% landscape, checking the exact query, actual served editor and unchanged provider bytes. Portrait Done operates while the keyboard is shown; landscape uses Android's fullscreen editor, returns with Back, then closes with the dialog Done. Direct captures were inspected and added to the screenshot record. Physical/IME variation remains in the beta checklist.
