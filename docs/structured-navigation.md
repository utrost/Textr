# JSON and XML structure navigation

Open **More options → Structure** for a JSON or XML document. Select a native list row for expand/collapse, jump to its original source line, copy path or copy exact source value. List rows announce level, type, original line and expansion state. Keyboard and screen-reader activation use the same native actions. Expanded nodes and list position survive activity recreation when the source fingerprint matches. Opening another source dismisses its tree.

Navigation is optional and bounded to 256 Ki UTF-16 characters, 2,000 nodes (including XML attributes), 64 levels and 256 Ki aggregate path characters. Parsing runs on the cancellable document worker. The native list recycles visible rows. Malformed, unsupported and over-budget input gets an unavailable explanation; complete source remains readable. Copying is explicit and limited to 64 Ki characters per value; larger values can be selected in source. Paths are similarly bounded by the aggregate parse budget. Nothing is automatically copied or stored as document content.

JSON retains source order and duplicate keys. Paths use a documented Textr syntax: `$` is the root; `["key"]@1` is the first occurrence of a JSON-quoted object key, `@2` the second; `[0]` is the first array item. This is an occurrence-aware display path, not a claim of JSONPath interoperability. A copied value is its exact lexical source slice, including JSON quotes/escapes, numeric exponent spelling and a complete object's/array's whitespace. No number conversion or key merging occurs.

XML paths use `/{"namespace URI"}localName[1]`, with one-based sibling occurrence counts among elements sharing that expanded name. Each namespace URI is JSON-quoted to distinguish punctuation and escaped characters. Attributes append `/@{"namespace URI"}localName`; unprefixed attributes have an empty namespace URI. Namespace declarations establish scope but are not separate attribute rows. Element values copy the complete original markup range; attribute values copy the original text between quotes, retaining entity/character-reference spelling. No whitespace normalization is applied to copied source.

All DTD/entity/other declaration markup is rejected before SAX parsing. Comments, CDATA and processing instructions are lexed separately; text resembling a declaration inside them is not interpreted. SAX validates XML and namespaces, external entity features are disabled where exposed, and a fail-closed resolver rejects every external URI. Built-in XML character references remain supported; there is no DTD expansion, network/file resolution, schema loading or XInclude processing.
