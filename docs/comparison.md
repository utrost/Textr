# Read-only document comparison

Included in 0.2-alpha. This feature compares two explicit, bounded snapshots of decoded source. It does not merge, edit, interpret a patch or communicate with Git.

The engine uses the budgets fixed before implementation: normal reading still accepts 5 MiB; comparison accepts at most 512 KiB original bytes and 256 Ki UTF-16 characters per input (1 MiB bytes / 512 Ki characters combined), 10,000 physical lines per input and 16,384 UTF-16 characters per physical line. A deterministic Myers shortest-edit-script search is limited to edit distance 512 and 2,000,000 frontier/character comparisons, with at most about 2.1 MiB of integer frontier history. Source ranges avoid copying every line. Cancellation is checked throughout splitting/hashing, search and reconstruction. Any exceeded budget makes comparison unavailable; an unfinished search is never reported as equal.

Equality means exact decoded UTF-16 text, including CRLF, LF, CR, whitespace, Unicode spelling and whether the final line ends. There is no case folding, Unicode normalization, whitespace ignoring or newline normalization. Byte encodings and BOMs can differ despite identical decoded text and must be identified separately. Line terminators belong to their preceding line; an empty document has zero lines, and a final terminator does not manufacture another empty line. Repeated-line tie breaking is stable: deletion precedes insertion when candidate frontiers tie.

A single active comparison screen bounds snapshots across activity launches. The native interface explicitly chooses both inputs from the reader snapshot, open URI references or Android picker. It displays names, encoding/BOM indicators and captured versions, read-only source additions/deletions with non-color labels, next/previous change controls, keyboard activation and explicit copy actions. Snapshot contents stay in memory; saved state contains only references, fingerprints and selection/position metadata. Process recreation rereads available URI sources and warns/reset positions if their contents changed; ephemeral shared content requires selection again. Unavailable grants/providers allow replacing an input. Comparison never takes a write grant or changes original sharing.

Unified view is the baseline. Side-by-side view uses a single virtualized list of aligned row pairs, so vertical scrolling and change selection are inherently linked. Narrow/short windows, 200% system text and large reader font settings use unified view. Resizing preserves selected change and snapshots. Physical foldable/speech-quality acceptance remains part of #56.

Validation: four native comparison tests passed on API 29 and API 36. They cover actual picker selection, exact line copying (including CRLF), next/previous and keyboard navigation, source-byte integrity, metadata-only state, retained snapshots, reread/changed-version warnings, shared-snapshot loss, denied/oversize inputs, cancellation and recovery, linked wide layout and unified 200% compact fallback with retained change selection. Debug compilation, the JVM suite and lint passed. The framework keyboard-dispatch override follows the existing reader pattern; the inherited AndroidX library restriction is suppressed only on that public Activity hook.
