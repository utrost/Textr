# Read-only document comparison

Included in 0.2-alpha. This feature compares two explicit, bounded snapshots of decoded source. It does not merge, edit, interpret a patch or communicate with Git.

The engine uses the budgets fixed before implementation: normal reading still accepts 5 MiB; comparison accepts at most 512 KiB original bytes and 256 Ki UTF-16 characters per input (1 MiB bytes / 512 Ki characters combined), 10,000 physical lines per input and 16,384 UTF-16 characters per physical line. A deterministic Myers shortest-edit-script search is limited to edit distance 512 and 2,000,000 frontier/character comparisons, with at most about 2.1 MiB of integer frontier history. Source ranges avoid copying every line. Cancellation is checked throughout splitting/hashing, search and reconstruction. Any exceeded budget makes comparison unavailable; an unfinished search is never reported as equal.

Equality means exact decoded UTF-16 text, including CRLF, LF, CR, whitespace, Unicode spelling and whether the final line ends. The default performs no normalization. Optional display filters are described below; there is no case folding or Unicode normalization. Byte encodings and BOMs can differ despite identical decoded text and must be identified separately. Line terminators belong to their preceding line; an empty document has zero lines, and a final terminator does not manufacture another empty line. Repeated-line tie breaking is stable: deletion precedes insertion when candidate frontiers tie.

A single active comparison screen bounds snapshots across activity launches. The native interface explicitly chooses both inputs from the reader snapshot, open URI references or Android picker. It displays names, encoding/BOM indicators and captured versions, read-only source additions/deletions with non-color labels, next/previous change controls, keyboard activation and explicit copy actions. Snapshot contents stay in memory; saved state contains only references, fingerprints and selection/position metadata. Process recreation rereads available URI sources and warns/reset positions if their contents changed; ephemeral shared content requires selection again. Unavailable grants/providers allow replacing an input. Comparison never takes a write grant or changes original sharing.

Unified view is the baseline. Side-by-side view uses a single virtualized list of aligned row pairs, so vertical scrolling and change selection are inherently linked. Narrow/short windows, 200% system text and large reader font settings use unified view. Resizing preserves selected change and snapshots. Physical foldable/speech-quality acceptance remains part of #56.

Validation: four native comparison tests passed on API 29 and API 36. They cover actual picker selection, exact line copying (including CRLF), next/previous and keyboard navigation, source-byte integrity, metadata-only state, retained snapshots, reread/changed-version warnings, shared-snapshot loss, denied/oversize inputs, cancellation and recovery, linked wide layout and unified 200% compact fallback with retained change selection. Debug compilation, the JVM suite and lint passed. The framework keyboard-dispatch override follows the existing reader pattern; the inherited AndroidX library restriction is suppressed only on that public Activity hook.

## Draft review and filters

In the copy editor, **Compare original** captures the current draft against the original decoded snapshot from the start of that editing session. Undo history and caret stay in the editor. Provider changes do not redefine the original. The initial snapshot (including encoding/BOM metadata) is retained inside the same bounded recovery file. Older recovery files without a baseline explicitly disable this action. Comparison process loss discards its in-memory pair; return to the editor to open it again. Snapshot transfer uses an opaque token, never source text in an intent.

**Ignore whitespace** ignores ASCII spaces and tabs anywhere within a line. It does not remove blank lines or other Unicode whitespace. **Ignore line endings** ignores CR/LF/CRLF differences and a missing final terminator. Options are independent and affect only the displayed change calculation; original snapshots and ranges remain exact. “Equivalent with filters” is distinct from identical decoded text. Options survive recreation and remain subject to the existing cancellation/work limits.

## Export changes

**Export patch** writes a standard unified diff of the exact snapshots through Android’s create-document picker. If filters are active, confirmation explains that the patch includes their hidden differences. A patch has anonymous `a/original` and `b/modified` headers, three context lines and standard missing-final-newline markers; filenames and provider paths are not exposed. Output is UTF-8, bounded to 512 Ki UTF-16 characters / 1 MiB bytes. LF delimits patch lines; CR bytes stay in line bodies so CRLF/CR inputs remain exact when applying with a binary-preserving patch tool (for example GNU `patch --binary`). The patch does not transcode the destination file’s original encoding or BOM automatically.

Export never overwrites either selected input or the draft’s original URI. Cancelled/failed exports leave snapshots, filters and navigation intact. A successful save offers **Open saved copy**; denied read access shows ordinary reader recovery and does not undo the completed write. Patch application and merging remain outside Textr. The JVM fixtures are independently applied with GNU patch by `scripts/verify-patch-fixtures.py`.
