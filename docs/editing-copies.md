# Editing text and Markdown copies

Design for #90–#94, recorded before editor implementation. The original reader remains read-only. Editing is an explicit **Edit a copy…** action for original TXT/Markdown source, with a separate native editor. HTML reading conversions must first be exported and reopened as Markdown. The editor never writes to its input URI; every save uses the existing create-document flow and original-URI guard.

## Bounded state and recovery

Editing accepts at most 256 Ki UTF-16 characters, 10,000 physical lines and 4,096 UTF-16 characters per line. The line budgets apply to initial input, typing/paste and replacements; exceeding any budget leaves text unchanged. Normal reading still accepts 5 MiB. Undo and redo retain at most 20 operations and 1 Mi UTF-16 characters of change payload in total; undo history is session-only. Operations preserve selection and replacement is one undo step. Editing pauses during destination selection and writing; a successful save only clears the matching draft identity and revision. Cancelled, failed, interrupted or stale saves retain recovery.

There is one active editor and one active comparison screen across the activity stack. There is one private recovery draft. Starting another requires resolving the existing draft first; no age-based eviction removes the only unsaved copy. Before creation, the editor explains that source contents will be stored privately for recovery. The checkpoint lives under `noBackupFilesDir`, uses an atomic file replacement, and includes text, original URI/name, encoding/BOM/newline policy, revision, caret/selection and timestamp. It is excluded from backup and is independent of reader recents. No document contents enter intents, activity saved-state Bundles, analytics or logs. The editor's text view disables automatic state saving. Process restoration reads the last completed checkpoint; keystrokes not yet checkpointed can be lost. Disk failure leaves the prior checkpoint intact and shows an explicit recovery warning. Discard and a confirmed save of the matching revision remove the recovery copy. Clearing app data or uninstalling also removes it.

Checkpoint writes run off the UI thread, coalescing queued revisions to the latest snapshot. A draft is recoverable without access to its original provider. Home offers an explicit resume action. Back/navigation with a dirty buffer offers Save a copy, Discard, or Cancel; destination cancellation returns to the dirty editor. A clean editor can close normally; an unchanged private recovery copy remains available until explicit Discard or confirmed Save as. A blocked new-copy request can be cancelled without deleting the existing recovery copy. An unreadable/corrupt checkpoint is preserved until a separate confirmed discard.

## Text fidelity and output

Existing characters, whitespace and newline sequences remain intact. New LF input uses the source's uniform CRLF or CR convention; LF and mixed-ending documents insert LF. Pasted existing CRLF/CR sequences are retained. The UI identifies encoding, BOM and newline policy. Supported output encodings are UTF-8, UTF-16LE, UTF-16BE, Windows-1252 and ISO-8859-1, with BOM only for Unicode encodings. The initial choice matches the source. Unrepresentable characters fail visibly rather than being substituted. Output preserves text and the chosen encoding/BOM; save success is reported only after encoding, provider write and close succeed. A provider may retain a partial newly created file when best-effort cleanup fails.

## Find and replace

Find and replacement are literal, with optional case sensitivity and whole-word matching. No regular expressions. Queries are limited to 1,000 characters and replacement input to 4 Ki characters. Match navigation is bounded and reports its limit; replace-all must either finish entirely within the character limit as one undoable operation or leave the buffer unchanged. Search and replacement operate on the source buffer, including its real newline characters. Reader and editor share linear-time, code-point-aware KMP matching, simple Unicode case folding and combining-mark-aware whole-word boundaries. Replace all counts the complete buffer without allocating one range per match; more than 20 matches requires confirmation. Query/replacement state survives rotation in memory, without entering saved-state Bundles or private history.
