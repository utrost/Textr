# Save as a new document

**Save Markdown as…** exports the converter's actual Markdown reading content through Android's Create document picker. It writes UTF-8 without a BOM, suggests a sanitized `.md` name, and uses `text/markdown`. Local and shared HTML are eligible when conversion completes within its existing budgets. An unavailable-conversion action explains why export cannot proceed. Images, scripts, forms, hidden content and unsupported structures follow the same omission/link policy as the reading view; inspect the result before reusing it. The generated WebView HTML is never converted back into Markdown.

This is an explicit extension from reading/sharing to creating a user-selected output file. Source files remain read-only. The app requests neither broad storage nor directory access and does not retain a destination write grant. It refuses the original URI and recognized document-ID aliases before opening a writer. Android's normal Create document UI creates a new name when the suggested name already exists; providers control their own implementation. Original sharing still copies original bytes.

Encoding and writing run on a retained worker and are bounded to 5 MiB output. Text encoders report malformed/unrepresentable characters instead of replacing them. Writes use cancellable descriptors and bounded chunks, and success is reported only after stream completion, error checking and close. Cancel/denied-write/provider/storage failures preserve the input and attempt to delete the new partial document. Cleanup is best effort and has a bounded wait; when it cannot be confirmed, the UI identifies a potentially incomplete output for inspection/removal in the file manager. A URI with a still-running cleanup cannot be reused by another operation in the retained session.

Pending content stays in a retained ViewModel across rotation and while the picker is open. Instance state/history never stores that content. A private, bounded one-operation record stores only filename, destination reference, outcome and optional edit-session identity/revision. It reports an interrupted write after process death, or a confirmed completed result if that had already been recorded. A picker result arriving after the content snapshot was lost is not silently populated with reconstructed/empty text: its newly selected empty document is cleaned up where possible and interruption is reported. Acknowledging the result clears that operation record.

App backups/transfers are disabled. No persistent content-bearing export cache is created. External document providers can independently use the network; the app still has no network permission.

See [Android document storage](https://developer.android.com/training/data-storage/shared/documents-files) and [descriptor error reporting](https://developer.android.com/reference/android/os/ParcelFileDescriptor) for platform contracts. A completed stream is evidence that the provider accepted it, not an independent guarantee about a remote provider's eventual cloud sync/durability.
